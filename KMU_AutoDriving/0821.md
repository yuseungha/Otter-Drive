# 2026-08-21 통합 자율주행 작업 정리

## 1. 구현 결과

카메라 차선 주행, 라이다 라바콘 주행, 라이다 장애물 회피를 하나의 상태
머신과 Pure Pursuit 제어기로 통합했다.

현재 상태는 다음 세 가지다.

```text
LANE              기본 카메라 차선 주행
OBSTACLE_AVOID    비라바콘 장애물의 반대 차선으로 우회
CONE              두 줄의 라바콘 중앙 경로 주행
```

세 상태 모두 선택된 경로를 공통 Pure Pursuit 제어기로 추종한다. 라이다는
모든 상태에서 계속 수신하며, YOLO는 `LANE`과 `OBSTACLE_AVOID`에서 실행하고
`CONE`에 들어갔을 때만 카메라 구독과 추론을 멈춘다. 이때 모델은 GPU/메모리에
그대로 유지하므로 차선 주행 복귀 시 다시 로드하지 않는다.

## 2. 상태 전환

```text
LANE
 ├─ 가까운 라바콘 한 쌍과 유효한 중앙 경로 감지 → CONE
 └─ 현재 경로 근처에서 비라바콘 군집 감지       → OBSTACLE_AVOID

OBSTACLE_AVOID
 ├─ 가까운 라바콘 한 쌍과 유효한 중앙 경로 감지 → CONE
 └─ 장애물이 0.60초 동안 사라짐                 → LANE

CONE
 └─ 라바콘 두 줄 또는 중앙 경로가 0.80초간 끊김 → LANE
```

라바콘 진입 조건이 장애물 회피보다 우선한다. 기본 라바콘 진입 거리 기준은
차량 전방 `0.90m`다.

## 3. 기본 차선 주행

- 실행 시작 상태는 `LANE`이다.
- `center_lane_best.pt` YOLO segmentation 모델의 `center`, `lane` 마스크를
  사용한다.
- 영상에서 계산한 경로를 카메라-지면 투영 설정으로 `base_link` 기준 미터
  좌표의 `/planning/lane_path`로 변환한다.
- Pure Pursuit의 차선 lookahead는 `0.55m`다.
- 라이다는 차선 주행 중에도 계속 동작하여 라바콘과 비라바콘 장애물을
  감시한다.

## 4. 라바콘 주행

- 라이다에서 좌우 라바콘 줄을 구분하고 두 줄의 가운데를
  `/perception/cone_path`로 만든다.
- 가까운 좌우 라바콘 한 쌍과 유효한 중앙 경로가 확인되면 `CONE`으로
  전환한다.
- 기본 라바콘 쌍 폭 범위는 `0.35~1.20m`다.
- `CONE`에서는 YOLO 카메라 구독을 해제하지만 라이다 처리는 계속한다.
- Pure Pursuit의 라바콘 lookahead는 `0.35m`다.
- 라바콘 줄과 경로가 끊긴 상태가 `0.80초` 지속되면 `LANE`으로 복귀한다.

## 5. 장애물 차량 회피

장애물 차량은 별도의 YOLO 의미 분류가 아니라 요청한 기하학 규칙으로
판정한다.

1. 라이다의 유효 영역 점들을 받는다.
2. 원시/확정 라바콘 중심 반경 `0.20m` 안의 점을 제거한다.
3. 남은 점을 거리 `0.14m` 기준으로 군집화한다.
4. 최소 3개 점이며 폭이 `0.08~1.20m`인 군집을 후보로 삼는다.
5. 전방 `0.20~2.00m`에서 현재 주행 경로 중심 좌우 `0.15m` 안에 들어온
   비라바콘 군집을 장애물 차량으로 확정한다.

차량 폭은 카메라/경로 중심 기준 좌우 `0.15m`, 전체 `0.30m`로 적용했다.
장애물이 경로 왼쪽에 있으면 오른쪽으로, 오른쪽에 있으면 왼쪽으로
회피한다. 중앙에 있으면 기본적으로 왼쪽을 선택한다.

우회 경로는 카메라가 만든 원래 차선 경로를 반대 차선 쪽으로 `0.55m`
이동하여 만든다. 급격히 꺾이지 않도록 전방 `0.80m` 구간에서 smoothstep
방식으로 횡방향 이동량을 증가시킨다. `OBSTACLE_AVOID`에서도 YOLO와
라이다는 모두 계속 실행한다.

## 6. Pure Pursuit와 주행 출력

주요 기본값은 다음과 같다.

| 항목 | 설정값 |
|---|---:|
| 휠베이스 | `0.20m` |
| 차선/장애물 목표 속도 | `0.15m/s` |
| 라바콘 목표 속도 | `0.12m/s` |
| 최소 계산 속도 | `0.08m/s` |
| 최대 조향각 | `35도` |
| 최대 조향 변화율 | `3.0rad/s` |
| 제어 출력 주기 | `20Hz` |

주행 명령 메시지는 `std_msgs/msg/Int32MultiArray`이며 배열 형식은
`[throttle, steering]`이다.

| 상태 | throttle 범위 | steering 범위 |
|---|---:|---:|
| `LANE` | `280~550` | `-650~650` |
| `OBSTACLE_AVOID` | `280~550` | `-650~650` |
| `CONE` | `280~500` | `-650~650` |

현재 `steering_sign`은 `-1`이므로 소프트웨어 설정상 왼쪽 경로는 음수,
오른쪽 경로는 양수 조향 count로 변환된다. 직진은 `0`이다.

경로가 일시적으로 없어져도 통합 Pure Pursuit는 최소 전진 출력과 마지막
조향 요구를 유지한다. 이번 플래너에는 라바콘 접촉이나 경로 손실을 이유로
정지하는 로직을 추가하지 않았다. Live 실행에서는 Arduino 브리지의
reset/펌웨어 확인 후 `/rc_car/serial_ready=true`가 되는 즉시 arm/deadman을
자동 활성화하고 최소 전진 출력부터 전달한다. 별도 수동 arm 명령은 없다.
기존 실행 스크립트의 장치 확인과 Arduino 출력 범위 제한은 그대로 존재한다.

## 7. 주요 ROS 토픽

### 입력/인지

| 토픽 | 형식/용도 |
|---|---|
| `/camera/front/image_raw` | 전방 카메라 영상 |

| `/planning/lane_path` | YOLO 기반 차선 경로 |
| `/perception/cone_path` | 두 라바콘 줄의 중앙 경로 |
| `/cone_planner/cones` | 확정 라바콘 중심 |
| `/cone_planner/raw_cones` | 원시 라바콘 후보 |
| `/perception/lidar_obstacle_points` | 라이다 유효 영역의 원시 장애물 점 |

| 토픽 | 형식/용도 |
|---|---|
| `/mission/state` | `LANE`, `OBSTACLE_AVOID`, `CONE` |

| `/planning/pure_pursuit_target` | 현재 lookahead 목표점 |
| `/perception/obstacle_vehicle` | 장애물 판정과 위치 JSON |

| `/rc_car/drive_cmd_preview` | dry-run의 `[throttle, steering]` |

## 8. 실행 방법

프로젝트 위치:

```bash
cd /home/sandi/KMU_AutoDriving
```

구동 출력을 연결하지 않고 전체 인지/계획/제어 출력 확인:

```bash
./scripts/run_competition.sh --unified-dry-run
```

실제 Arduino 출력 연결:

```bash
./scripts/run_competition.sh --unified-live
```

Live 실행에는 기존 스크립트 요구사항에 따라 올바른 카메라, 라이다,
Arduino 장치 경로와 `KMU_HARDWARE_CONFIRMED=true` 설정이 필요하다. 실행 후
serial reset/펌웨어 확인이 끝나면 통합 노드가 자동으로 arm/deadman을 켜고
모터 출력을 시작한다.

다른 터미널에서 출력 확인:

```bash
export ROS_DOMAIN_ID=86
source /opt/ros/humble/setup.bash
source /home/sandi/KMU_AutoDriving/.colcon/install/setup.bash

ros2 topic echo /mission/state
ros2 topic echo /rc_car/drive_cmd_preview
ros2 topic echo /perception/obstacle_vehicle
ros2 topic echo /vehicle/unified_autonomy_status
```

Live 모드에서는 `/rc_car/drive_cmd_preview` 대신 `/rc_car/drive_cmd`를 확인한다.

## 9. 신호등 인식 상태

현재 통합 주행 YOLO 모델에는 신호등 클래스가 없다.

- `center_lane_best.pt`: `center`, `lane`
- `road_best.pt`: `lane1`, `lane2`

프로젝트에는 고정 ROI와 HSV 색상 규칙을 사용하는 별도의
`traffic_light_node.py`가 있지만 현재 `unified_autonomy.launch.py`와 세 상태
머신에는 연결하지 않았다. 따라서 현재 통합 주행은 신호등 상태에 따라
정지하거나 출발하지 않는다.

## 11. 검증 결과와 남은 조정

- `lidar_cone_planner`, `kmu_track` 패키지 빌드 성공
- `colcon test-result`: 총 183개 테스트, 오류 0, 실패 0
- launch 인자와 통합 노드 초기화 확인
- 실제 센서가 연결된 차량 주행은 아직 검증하지 않음

실제 코스에서 우선 확인할 값:

1. 카메라 영상-지면 투영값
2. 라이다와 `base_link` 사이 위치/방향
3. 실제 차선 폭에 맞는 `opposite_lane_offset_m` (`0.55m`)
4. 라바콘 쌍 폭과 진입 거리
5. 라이다 장애물 군집 거리와 최소 점 개수
6. 조향 중앙, 방향 부호, 최대 count

현재 장애물 차량 판정은 의미론적 차량 인식이 아니라 “경로를 차지하는
비라바콘 라이다 군집”이라는 가정에 기반한다. 사람, 벽 또는 다른 물체도
같은 조건을 만족하면 장애물 차량으로 처리한다.
