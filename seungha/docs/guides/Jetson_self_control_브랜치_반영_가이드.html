GitHub branch: self-control

Jetson 코드 반영 및 수동주행 실행

모니터를 Jetson에 연결한 뒤 GitHub에서 브랜치를 확인하고, Jetson 터미널에서 pull·빌드·실행하는 절차입니다.

이번 반영 내용

항목반영값
W/S 속도 증감THROTTLE_STEP = 30
A/D 조향 증감STEERING_STEP = 100
GitHub 저장소yuseungha/KMU_AutoDrive · self-control

1. Jetson에서 GitHub 브랜치 확인

  1. Jetson에 모니터와 키보드를 연결하고 Ubuntu에 로그인합니다.
  2. 브라우저에서 self-control 브랜치를 엽니다.
  3. rc_car_teleop/keyboard_teleop.py의 THROTTLE_STEP = 30을 확인합니다.
  4. GitHub 웹 화면의 확인이 끝나면 Jetson의 Terminal에서 pull을 실행합니다.

GitHub 웹 페이지는 브랜치 확인용이며, 실제 pull은 Terminal에서 수행합니다.

2. Jetson Terminal에서 저장소와 브랜치 확인

현재 수동주행 실행 워크스페이스가 GitHub 저장소의 체크아웃인지 먼저 확인합니다.

cd /home/sandi/ros2_ws
git rev-parse --show-toplevel
git remote -v
git status -sb

remote가 https://github.com/yuseungha/KMU_AutoDrive.git이고, 작업 루트가 확인되면 다음 단계로 진행합니다.

3. self-control 브랜치 pull

cd /home/sandi/ros2_ws
git fetch origin --prune
git switch self-control
git pull --ff-only origin self-control

로컬에 브랜치가 없으면 다음을 한 번 실행한 뒤 다시 pull합니다.

git switch --track -c self-control origin/self-control

4. 코드 반영값 확인

grep -n "THROTTLE_STEP\|STEERING_STEP" \
  /home/sandi/ros2_ws/src/rc_car_teleop/rc_car_teleop/keyboard_teleop.py

정상 결과: THROTTLE_STEP = 30, STEERING_STEP = 100

5. Jetson ROS 2 재빌드

cd /home/sandi/ros2_ws
source /opt/ros/humble/setup.bash
PYTHONNOUSERSITE=1 colcon build --symlink-install \
  --packages-select kmu_track rc_car_teleop laptop_teleop
source install/setup.bash

6. 수동주행 실행

docker exec -it sanditest bash \
  /root/ros2_ws/src/laptop_teleop/scripts/container_existing_manual.sh
키동작
W / S속도값을 30씩 증가 / 감소
A / D조향값을 100씩 좌 / 우 변경
Space속도 정지
C조향 중앙
X속도 정지 및 조향 중앙
Q 또는 Ctrl+C수동주행 종료

7. pull이 불가능할 때

not a git repository가 나오거나 remote가 다르면 해당 경로에서 임의로 git init하지 않습니다. 실제 Git checkout 경로를 확인한 뒤, 그 저장소 루트에서 2~5단계를 실행합니다.

find /home/sandi -path '*/.git' -type d 2>/dev/null
git -C /실제/저장소/경로 remote -v
